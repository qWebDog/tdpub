# Админка to Dublin на PHP-хостинге

Эта админка сохраняет выбранные фотографии и цены прямо в файлы сайта. Она работает после переноса сайта на хостинг с PHP. GitHub Pages PHP не выполняет: по адресу `/admin/` на нём открывается информационная страница, без входа, загрузки фотографий и сохранения изменений.

На PHP-хостинге открывайте `/admin/index.php`. Для Apache порядок `DirectoryIndex index.php` уже указан в `.htaccess`; для Nginx при необходимости настройте такой же порядок индексных файлов у хостинга. Файл `admin/index.html` предназначен для статического размещения и не является страницей входа.

## Требования

- PHP 8.1 или новее, расширения Session, Fileinfo и JSON; `getimagesize`. GD не требуется.
- HTTPS. Небезопасный HTTP разрешён только для локальной разработки на localhost/127.0.0.1/::1.
- Хостинг и место хранения фотографий, данных и резервных копий — в России, согласно выбранному владельцем ограничению. Расположение конкретного сервера необходимо проверить у хостинга.
- PHP-процесс должен читать `data/site-content.json` и записывать в папку `data` и `media/gallery/photos`. Не используйте права 777.
- Приватный каталог с правами 700 **вне webroot**, доступный PHP. В нём хранятся хеш пароля, сессии и защита от перебора; его нельзя добавлять в GitHub или в публичный архив сайта.

## Перенос и настройка входа

1. Загрузите весь сайт, включая папки `admin`, `data`, `media/gallery/photos`, на хостинг. Сохраните существующий `data/site-content.json`, если в нём уже есть рабочие цены и порядок фотографий: повторная загрузка старого файла заменит эти настройки.
2. Укажите серверную переменную `TO_DUBLIN_PRIVATE_DIR`, например `/home/ACCOUNT/to-dublin-private`. Это должен быть путь выше/вне `public_html`, `www` или другого публичного каталога. Настройка переменной зависит от панели хостинга; используйте инструкции провайдера. По умолчанию выбирается `to-dublin-private` рядом с корневой папкой проекта; если сайт находится во вложенной публичной папке, обязательно задайте безопасный путь вручную. Backend откажется работать, если определит размещение приватного каталога внутри webroot.
3. Через SSH в каталоге сайта выполните:

   ```sh
   php admin/manage.php set-password
   ```

   Если переменная пути ещё не задаётся окружением командной строки:

   ```sh
   TO_DUBLIN_PRIVATE_DIR=/home/ACCOUNT/to-dublin-private php admin/manage.php set-password
   ```

   Введите новый пароль дважды. Пароль читается из stdin и не печатается. В репозиторий и публичный JavaScript он не попадает. Для нового пароля используйте 12–72 байта; лучше длинную уникальную ASCII-фразу. Не передавайте пароль аргументом команды или в чате.
4. Проверьте, что PHP сайта использует **тот же** `TO_DUBLIN_PRIVATE_DIR`, что и команда настройки. Если папки по умолчанию достаточно, отдельная переменная не нужна. Если у хостинга нет SSH, попросите поддержку выполнить CLI-команду с безопасным вводом или согласуйте другой закрытый способ установки пароля. Публичного мастера установки и стандартного пароля нет.
5. Откройте `https://ВАШ-ДОМЕН/admin/`, войдите, проверьте загрузку списка файлов и сохранение тестового изменения. Настройки изменяют сайт только после успешного сохранения. Пароль можно сменить той же CLI-командой; старые сессии перестанут действовать.

## Фотографии

Можно загрузить файлы через админку или заранее положить их в `media/gallery/photos` через менеджер хостинга/FTP. После обновления списка допустимые файлы появятся в админке.

- JPEG, PNG, WebP; максимум 10 МБ и 40 мегапикселей на файл, до 20 000 пикселей по каждой стороне.
- Не поддерживаются SVG, HEIC, GIF, архивы, подпапки, символические ссылки и файлы с неподходящим MIME. Файл `.jpg` должен действительно быть JPEG.
- До 10 файлов за один запрос, суммарно до 40 МБ. PHP/веб-сервер могут ограничивать запрос сильнее. Для крупных загрузок проверьте `upload_max_filesize`, `post_max_size`, `max_file_uploads` и лимит тела запроса веб-сервера. При небольших лимитах загружайте по одному файлу.
- При загрузке через админку файлы получают уникальные безопасные имена. Существующие файлы не заменяются и не удаляются.
- В папке допускается до 1000 поддерживаемых фотографий; в опубликованной галерее — до 100.
- Не включённый в галерею файл всё равно доступен по своему публичному URL. Скрытие из галереи не делает изображение приватным. Конфиденциальные файлы в эту папку не загружайте.
- Порядок массива `gallery.items` определяет порядок кадров. Подпись — до 120 символов, описание для доступности — до 240.

## Цены и сохранение

`data/site-content.json` содержит только публичные настройки:

```json
{
  "schemaVersion": 1,
  "pricing": {
    "base": 150000,
    "generatorDiscount": 20000,
    "barrelDiscount": 5000,
    "extraHour": 15000,
    "extraKeg": 9000
  },
  "gallery": { "items": [] }
}
```

Цены — целые рубли от 0 до 100 000 000, дополнительный кег — не меньше 1 рубля. База должна покрывать максимальную скидку за генератор и семь бочек, чтобы итог не оказался отрицательным. Базовые восемь часов и количество включённого оборудования этой страницей не меняются.

Backend проверяет вход, CSRF и происхождение запросов, валидирует цены/фотографии и записывает файл атомарно. Версия `revision` защищает от незаметной перезаписи изменений другой вкладкой. При конфликте загрузите актуальные настройки, затем повторите свои изменения.

Сессия завершается после часа бездействия или восьми часов с момента входа. Восемь неудачных входов с одного IP блокируют вход с этого IP до конца 15-минутного окна. Не используйте общий пароль с другими сервисами.

## API для интерфейса

Все ответы — JSON. Успех: `{ "ok": true, ... }`; ошибка: `{ "ok": false, "error": "…", "code": "…" }` с соответствующим HTTP-статусом. CORS-доступ из других сайтов не включён.

- `GET api.php?action=session`: `configured`, `authenticated`, `csrf` после входа.
- `POST api.php?action=login`, JSON `{ "password": "…" }`: статус и новый CSRF-токен.
- `POST api.php?action=logout`, JSON `{}`, `X-CSRF-Token`.
- `GET api.php?action=content`: `content`, `revision`, `files` после входа. В `files`: `file`, `width`, `height`, `bytes`, `url`, относительный к странице админки.
- `POST api.php?action=save`, JSON `{ "content": {…}, "revision": "…" }`, `X-CSRF-Token`: сохранённые `content` и `revision`.
- `POST api.php?action=upload`, `multipart/form-data`, поля `photos[]`, `X-CSRF-Token`: только новые `files`.

Все POST должны исходить с этого же сайта. Куки только HTTP-only, SameSite=Strict и Secure на HTTPS. Перед админкой не должно быть общего CDN-кеша API. Не включайте wildcard CORS и не помещайте пароль/хеш/сессионные файлы в публичную папку.
